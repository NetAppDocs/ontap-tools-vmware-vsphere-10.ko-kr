= ONTAP tools를 사용하여 클러스터의 데이터 저장소 보호
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
호스트 클러스터에 여러 스토리지 가상 머신(SVM)의 데이터스토어가 포함되어 있고 선택한 데이터스토어를 서로 다른 정책으로 보호해야 하는 경우 세분화된 데이터스토어 보호 기능을 사용하십시오.

.시작하기 전에
호스트 클러스터에서 데이터 저장소를 보호하기 전에 다음 요구 사항을 충족하는지 확인하십시오.

* 해당 데이터 저장소는 iSCSI 또는 FC 프로토콜을 사용하는 VMFS 데이터 저장소입니다.
* 데이터 저장소가 검색되어 ONTAP tools에서 사용할 수 있습니다.
* 소스 및 타겟 스토리지 VM은 SnapMirror 관계를 위해 구성되어 있습니다.


.단계
. vSphere 클라이언트에 로그인합니다.
. 호스트 또는 호스트 클러스터를 마우스 오른쪽 버튼으로 클릭하고 * NetApp ONTAP tools* > *데이터 저장소 보호*를 선택합니다.
. 클러스터에서 *스토리지 VM*을 선택합니다.
+
선택한 SVM의 데이터 저장소가 표시됩니다.

. *데이터 저장소 유형* 필드는 보호를 위해 지원되는 유일한 데이터 저장소 유형인 VMFS로 미리 채워져 있으며 비활성화되어 있습니다.
. 자격 기준에 따라 표시되는 목록에서 보호할 데이터 저장소를 선택하고 *다음*을 클릭합니다.
. *보호 설정* 창에서 선택한 데이터 저장소를 기존 보호 그룹 또는 새 보호 그룹으로 보호할지 여부를 선택합니다.
. *새로 만들기*를 선택한 경우 보호 그룹의 이름을 입력하고 *관계 추가*를 선택하십시오.
. SnapMirror 관계 추가 * 창에서 * 대상 스토리지 VM * 및 * 정책 * 유형을 선택합니다.
+
정책 유형은 비동기 또는 AutomatedFailOverDuplex일 수 있습니다. AutomatedFailOverDuplex는 iSCSI 또는 FC 프로토콜을 사용하여 ONTAP 9.15.1에 프로비저닝되고 호스트 클러스터에 마운트된 데이터스토어에 대해서만 지원됩니다.

+
SnapMirror 관계를 AutomatedFailOverDuplex로 추가하는 경우, ONTAP tools for VMware vSphere가 배포된 동일한 vCenter Server에 타겟 스토리지를 스토리지 백엔드로 추가하십시오.

+
AutomatedFailOverDuplex 정책 유형에는 균일 클러스터 구성과 비균일 클러스터 구성이 있습니다. 균일 클러스터 구성의 경우, 호스트 이니시에이터 그룹 구성이 타겟 클러스터 사이트에 복제됩니다. 자세한 내용은 link:../concepts/ontap-tools-concepts-terms.html["주요 개념 및 용어"]을 참조하십시오.

. 비균일 클러스터 구성의 경우 클러스터의 각 호스트에 대해 호스트 액세스(소스 또는 대상)를 선택하십시오. ONTAP tools는 대상 스토리지 객체에 대한 호스트 액세스를 제공하기 위해 대상 스토리지에 해당 호스트 이니시에이터 그룹 구성을 생성합니다.
. 저장 * 을 선택합니다.
. *요약* 창에서 구성을 검토하고 *보호*를 선택하십시오.
. 사용 가능한 모든 보호 그룹의 세부 정보를 보려면 * NetApp ONTAP tools* > *보호* > *보호 그룹*으로 이동하십시오.


.결과
선택한 데이터 저장소를 포함하는 새 보호 그룹이 생성되고 SnapMirror 관계가 해당 보호 그룹에 추가됩니다. 시스템은 vCenter 작업 ID 세부 정보가 포함된 vCenter 작업을 생성하고 최근 작업 패널에 진행 상황을 표시합니다. 이 작업은 비동기 작업이므로 사용자 인터페이스에는 요청 제출 상태만 표시되고 작업 완료를 기다리지 않습니다.

[NOTE]
====
ONTAP 스토리지(ONTAP 9) 클러스터의 경우, 보호 그룹이 비동기 관계를 갖는 경우 마지막 데이터 저장소가 아닌 데이터 저장소의 보호 해제는 지원되지 않습니다.
