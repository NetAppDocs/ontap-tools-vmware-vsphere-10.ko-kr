[[deployment-and-high-availability]]
== 배포 및 고가용성

.ONTAP 툴에서 지원되는 VMware vSphere, ESXi 및 ONTAP 버전은 무엇입니까?
지원되는 ONTAP, ESXi 및 vCenter Server 버전은 ONTAP 툴 릴리스에 따라 다릅니다. ONTAP 툴 가상 머신을 배포하는 데 사용되는 ESXi 호스트 및 vCenter Server는 배포 후 ONTAP 툴이 관리할 수 있는 버전보다 더 엄격한 별도의 요구사항을 가질 수도 있습니다. 지원되는 버전은 릴리스마다 변경되므로 항상 실행 중인 릴리스에 대한  https://mysupport.netapp.com/matrix["NetApp 상호 운용성 매트릭스 툴"^] 및 link:deploy/prerequisites.html["VMware vSphere 요구 사항 및 구성 제한에 대한 ONTAP 도구"]를 확인하십시오.

.ONTAP 툴 9.x와 10.x 중 어떤 버전을 사용해야 합니까?
대부분의 환경에서는 최신 ONTAP 툴 10.x 릴리스로 마이그레이션하는 것이 좋습니다. ONTAP 툴 9.13과 비교하여 VMFS용 NVMe-oF 지원이 추가되었고, 최신 ONTAP 및 VMware vSphere 릴리스와의 호환성이 확보되었으며, 어플라이언스당 단일 인스턴스가 아닌 여러 vCenter Server 인스턴스를 지원합니다. ONTAP 툴 9.x를 유지하는 것은 환경에 최신 10.x 릴리스가 아직 지원하지 않는 특정 종속성이 있는 경우에만 타당하며, ONTAP 툴 9.x의 지원 종료가 다가오고 있으므로 가능한 한 빨리 마이그레이션을 계획하는 것이 좋습니다. 현재 지원 종료 날짜는  https://mysupport.netapp.com/site/info/version-support["NetApp 지원 사이트 - 소프트웨어 버전 지원"^] 페이지를 확인하십시오. 사용 중인 ONTAP, ESXi 및 vSphere 버전에 맞는 버전을 확인하려면 link:release-notes/ontap-tools-9-ontap-tools-10-feature-comparison.html["버전별 VMware vSphere 기능 비교를 위한 ONTAP tools"] 및  https://mysupport.netapp.com/matrix["NetApp 상호 운용성 매트릭스 툴"^]을(를) 참조하십시오.

.요구사항이 증가함에 따라 ONTAP 툴 배포를 확장하려면 어떻게 해야 합니까?
ONTAP 툴은 처음에 항상 초소형(XS) 단일 노드 어플라이언스로 배포되어 NFS 및 VMFS 데이터스토어에 대한 핵심 서비스를 제공합니다. 나중에 더 많은 리소스, 더 높은 복원력 또는 vVols 및 HA가 필요한 경우 소형, 중형 또는 대형으로 스케일 업하거나 HA로 확장할 수 있습니다. HA 배포는 다중 노드 구성으로 3개의 노드를 사용하며 콘텐츠 라이브러리가 필요하고, 대형 배포는 HA를 통해서만 지원됩니다. HA 확장을 지원하려면 어플라이언스를 ESXi 클러스터 또는 리소스 풀에 배포하고 CPU 핫 추가 및 메모리 핫 플러그가 활성화되어 있는지 확인하십시오. ONTAP 툴 10.6부터는 새 배포 시 이러한 설정이 기본적으로 활성화됩니다. 각 크기에 대한 CPU, 메모리 및 디스크 리소스는 link:deploy/prerequisites.html["VMware vSphere 요구 사항 및 구성 제한에 대한 ONTAP 도구"]에 나열되어 있으므로 XS 기본값으로 시작하여 요구 사항이 증가함에 따라 확장하는 것이 안전합니다. ONTAP 툴은 스케일 업만 지원합니다. 노드 크기를 늘릴 수는 있지만 줄일 수는 없으며, HA를 활성화한 후에는 HA가 아닌 단일 노드 구성으로 되돌릴 수 없습니다. 배포, 사이징 및 확장 단계는 link:deploy/quick-start.html["VMware vSphere용 ONTAP 툴을 빠르게 시작합니다"], link:deploy/ha-workflow.html["ONTAP 도구의 고가용성 배포 워크플로"] 및 link:manage/edit-appliance-settings.html["ONTAP tools 확장 및 고가용성 활성화"]를 참조하십시오.

.고가용성은 무엇을 보호하며, 어떤 점을 고려해야 할까요?
HA 솔루션은 단일 노드 호스트 장애, 네트워크 장애, 게스트 OS 장애 또는 ONTAP 툴 애플리케이션 장애로부터 복구하는 데 도움이 되도록 고안되었습니다. HA 배포에는 세 개의 노드가 사용되며, 노드 간 통신을 위해 동일한 서브넷에 있어야 합니다. CPU 핫 추가 및 메모리 핫 플러그 기능이 활성화되어 있어야 하며, HA 워크플로에는 vVols 데이터스토어용 VASA Provider도 필요합니다. 설정 단계는 link:deploy/ha-workflow.html["ONTAP 도구의 고가용성 배포 워크플로"]을(를) 참조하십시오.

.고가용성(HA) 배포가 필요한가요? 필요하다면 언제 사용해야 할까요?
vVols 없이 NFS 또는 VMFS 데이터스토어만 사용하는 경우 HA는 필요하지 않지만, 단일 노드 호스트, 네트워크, 게스트 OS 또는 ONTAP 툴 애플리케이션 장애에 대해 더 넓은 복원력을 제공합니다. vVols 데이터스토어에 대해 VASA Provider 서비스를 지속적으로 사용 가능하게 유지하려면 HA가 필요하므로, vVols를 사용하거나 단일 노드 배포가 제공하는 것보다 더 높은 서비스 복원력과 서비스당 더 많은 컨테이너가 필요한 경우 HA 배포를 사용하십시오.

.ONTAP 툴 10.x 단일 배포 환경에서 여러 vCenter Server 인스턴스를 관리할 수 있습니까?
예. 어플라이언스당 하나의 vCenter Server만 지원하는 ONTAP tools 9.x와 달리, ONTAP tools 10.x는 멀티 테넌시(multi-tenancy)를 지원하며 단일 ONTAP tools Manager 인터페이스에서 여러 vCenter Server 인스턴스를 관리할 수 있어 어플라이언스 수와 전체 리소스 요구 사항을 줄일 수 있습니다. 여러 vCenter Server 인스턴스에서 vVols 데이터스토어를 사용하는 경우, 안전한 통신을 위해 자체 서명 인증서를 CA 서명 인증서로 업그레이드하십시오. 단계는 link:configure/add-vcenter.html["ONTAP 도구에 vCenter Server 인스턴스 추가"]을 참조하십시오.

== 네트워킹 및 포트

.ONTAP 툴 배포에 필요한 IP 주소는 총 몇 개이며, 각 IP 주소의 용도는 무엇입니까?
단일 노드 배포에는 동일한 서브넷에 있는 고유한 고정 IPv4 주소 3개가 필요합니다:

* *ONTAP 툴 IP*(이전 명칭: 로드 밸런서 IP): ONTAP 툴 관리자 (`https://<ONTAPtoolsIP>:8443/virtualization/ui/`), REST API, VASA 공급자, 스토리지 복제 어댑터(SRA) 및 vSphere 클라이언트 플러그인의 외부 엔드포인트입니다.
* *ONTAP 툴 가상 IP*(이전의 노드 상호 연결 IP): Kubernetes API 서버에 할당되며 Kubernetes 컨트롤 플레인의 가상 IP로 사용됩니다.
* *노드 IP*: 진단 셸 및 SSH 접속에 사용되는 노드 관리 주소입니다.


HA 배포에서는 두 번째 및 세 번째 노드 각각에 추가 노드 IP 주소가 하나씩 추가됩니다. ONTAP 툴 IP와 가상 IP는 모든 노드에서 공유됩니다. 전체 배포 워크시트는 link:deploy/prerequisites.html["VMware vSphere 요구 사항 및 구성 제한에 대한 ONTAP 도구"] 및 link:deploy/pre-deploy-checks.html["ONTAP 도구 배포 전 요구 사항"]을(를) 참조하십시오.

.ONTAP 툴은 어떤 네트워크 포트를 사용합니까?
ONTAP 툴은 ONTAP 툴 Manager, REST API, VASA Provider 및 vSphere Client 플러그인 백엔드를 위한 외부 패스스루 포트로 포트 443 및 8443을 노출합니다. 포트 요구 사항 표에 있는 나머지 포트는 어플라이언스의 Kubernetes 클러스터에서 내부적으로 사용되는 노드 간 포트입니다. 단일 노드 배포에서는 외부 액세스가 필요하지 않으며, HA 배포에서는 Pod 간 통신을 위한 UDP 8472를 포함하여 세 노드 모두 이러한 포트에서 서로 연결할 수 있어야 합니다. 전체 포트 표는 link:deploy/prerequisites.html["VMware vSphere 요구 사항 및 구성 제한에 대한 ONTAP 도구"]을(를) 참조하십시오.

== 인증서 및 보안

.ONTAP 툴은 vCenter Server 인증서에 대해 무엇을 요구합니까?
인증서는 연결하려는 서버의 신원을 증명하는 경우에만 연결을 보호합니다. SAN(Subject Alternative Name) 확장은 이러한 증명을 제공합니다. 즉, 인증서가 유효한 DNS 이름과 IP 주소를 나열합니다.

vCenter Server 시스템의 SSL 인증서는 다음 요구 사항을 충족해야 합니다:

* SAN에는 vCenter Server의 DNS 이름과 IP 주소가 포함됩니다.
* SAN에는 vCenter Server 기본 네트워크 식별자(PNID)가 포함되어 있으며, PNID는 DNS 이름과 일치합니다.
* SAN에 있는 모든 이름은 DNS에서 확인됩니다.


인증서에 SAN이 없거나 SAN이 vCenter Server의 DNS 이름, IP 주소 또는 PNID와 일치하지 않으면 ONTAP tools 작업이 인증서 유효성 검사 오류와 함께 실패합니다. 이 유효성 검사는 해제할 수 없습니다. vCenter Server 인스턴스를 추가하기 전에 vSphere Certificate Manager를 사용하여 SAN을 수정하십시오. 인증서 요구 사항 및 예시는 link:configure/add-vcenter.html["ONTAP 도구에 vCenter Server 인스턴스 추가"]을 참조하십시오.

.스토리지 백엔드를 추가할 때 인증서 유효성 검사가 실패하는 이유는 무엇이며, 어떻게 해결해야 하나요?
ONTAP tools는 기본적으로 스토리지 백엔드 인증서를 검증합니다. vCenter Server 인증서를 검증하는 것과 동일한 이유로, SAN 확장을 통해 해당 인증서가 어느 클러스터 또는 SVM 관리 LIF에 속하는지 확인합니다. 기본 ONTAP 자체 서명 인증서에는 SAN이 없는 경우가 많으므로, 스토리지 백엔드를 추가할 때 검증에 실패합니다.

유효성 검사 실패를 해결하려면:

* 클러스터 또는 SVM 관리 LIF의 IP 주소 또는 DNS 이름이 SAN에 포함된 인증서로 교체한 다음 스토리지 백엔드를 추가하거나 다시 추가할 때 업데이트된 인증서를 가져와 승인하십시오.
* 인증서를 즉시 교체할 수 없는 경우 유지 관리 콘솔에서 인증서 유효성 검사를 비활성화하십시오. 이렇게 하면 구성된 모든 스토리지 백엔드에 대한 유효성 검사를 우회하며 vCenter Server 인증서에는 적용되지 않습니다.


스토리지 백엔드 인증서를 갱신하기 전에 만료되면, ONTAP 툴은 더 이상 스토리지 시스템에 연결할 수 없으므로 스토리지 백엔드를 알 수 없음으로 표시합니다. 자세한 단계는 link:configure/add-storage-backend.html["ONTAP tools에 스토리지 백엔드 추가"] 및 link:manage/change-valid-flag.html["인증서 유효성 검사 플래그 변경"]를 참조하십시오.



[[datastores-and-storage-backends]]
== 데이터스토어 및 스토리지 백엔드

.어떤 데이터스토어 유형 및 프로토콜을 관리할 수 있습니까?
ONTAP 툴은 다음과 같은 데이터 저장소 유형 및 프로토콜을 지원합니다:

* *NFS*: NFSv3 및 NFSv4.1.
* *VMFS*: iSCSI, FC, NVMe/TCP 및 NVMe/FC.
* *vVols*: VASA Provider를 통해 프로비저닝 및 관리됩니다.


생성 단계는 link:configure/create-datastore.html["ONTAP tools에서 데이터 저장소를 생성합니다"]을(를) 참조하십시오.

.ONTAP 툴은 왜 이렇게 많은 igroup을 생성하며, 기존의 플랫 igroup을 사용할 수 있습니까?
ONTAP 툴은 설계상 중첩된 igroup 모델을 사용합니다:

* 상위 i그룹은 각 데이터스토어의 액세스를 나타내고, 하위 i그룹은 각 ESXi 호스트를 나타냅니다. LUN 매핑은 하위 i그룹에 적용됩니다.
* 이 구조를 통해 ONTAP 툴이 모든 데이터스토어에 대해 호스트 액세스를 중복하는 대신 여러 데이터스토어에서 호스트의 하위 igroup을 재사용할 수 있으며, ONTAP 툴에 마운트, 마운트 해제 및 호스트 업데이트 작업에 필요한 호스트별 세부 제어 기능을 제공합니다.
* ONTAP 툴로 관리되는 i그룹은  `otv_` 접두사를 사용합니다.


ONTAP tools가 검색하는 데이터스토어에 매핑된 플랫 igroup이 이미 있는 경우, ONTAP tools는 검색 중에 이를 변환합니다. 원래 igroup을  `otv_` 접두사가 붙은 하위 igroup으로 이름을 변경하여 유지하고, 기본 이니시에이터 매핑을 변경하지 않고 그 위에 상위 igroup을 생성합니다. 부트 LUN igroup 등 데이터스토어에 매핑되지 않은 igroup은 그대로 유지됩니다.

ONTAP 툴은 호스트 액세스를 추적하기 위해 이러한 부모-자식 구조에 의존하므로 ONTAP 툴에서 관리하는 igroup을 수동으로 이름 변경, 편집 또는 삭제하지 마십시오. 대신 ONTAP 툴 마운트, 마운트 해제 및 호스트 업데이트 워크플로를 사용하십시오. 자세한 내용은 link:manage/nested-igroups.html["ONTAP tools의 중첩 igroup 관리"] 및 link:manage/igroup-workflow.html["ONTAP tools가 igroup 및 엑스포트 정책을 관리하는 방법"]을(를) 참조하십시오.

.글로벌 스토리지 백엔드와 로컬 스토리지 백엔드의 차이점은 무엇인가요?
스토리지 백엔드는 범위와 자격 증명 측면에서 차이가 있습니다:

* *글로벌 스토리지 백엔드*: ONTAP 클러스터 자격 증명만 사용하여 ONTAP tools Manager에 한 번 추가됩니다. 사용자가 연결하기 전까지는 vCenter Server에 연결되지 않으며, vVols 관리에 필요한 클러스터 수준의 검색을 제공합니다.
* *로컬 스토리지 백엔드*: 클러스터 또는 SVM 자격 증명을 사용하여 vCenter Server별로 추가되며 해당 vCenter Server에서만 사용할 수 있습니다. VMFS 데이터스토어 및 스토리지 복제 어댑터(SRA) 워크플로에는 SVM 자격 증명만으로 충분하지만 vVols에는 그렇지 않습니다.


단계는 link:configure/add-storage-backend.html["ONTAP tools에 스토리지 백엔드 추가"] 및 link:configure/associate-storage-backend.html["ONTAP 도구에서 스토리지 백엔드를 vCenter Server 인스턴스에 연결합니다"]을(를) 참조하십시오.

.ONTAP 툴과 함께 vVols를 사용하려면 무엇이 필요합니까?
vVols 데이터스토어 워크플로는 VASA Provider 서비스가 활성화되어 있고 선택한 vCenter Server에 등록되어 있어야 합니다. ONTAP 툴은 VASA Provider를 사용하여 vVols 데이터스토어 표현을 생성 및 유지 관리하며, VM 스토리지 정책은 NetApp vVols 스토리지 유형 공급자의 규칙을 사용합니다. HA 구성에서는 HA 워크플로에도 vVols 데이터스토어용 VASA Provider가 필요합니다. 설정 단계는 link:manage/enable-services.html["ONTAP tools Manager에서 선택적 서비스를 활성화합니다."] 및 link:configure/registration-process.html["ONTAP 도구에서 VASA Provider를 vCenter Server 인스턴스에 등록합니다"]를 참조하십시오.

.VMware에서 vVols를 더 이상 사용하지 않습니다. 이는 ONTAP 툴 사용자에게 어떤 의미일까요?
Broadcom은 VMware Cloud Foundation 및 VMware vSphere Foundation 9.0부터 vVols를 더 이상 사용하지 않으며, 향후 릴리스에서 해당 기능을 중단할 계획입니다. 새로운 배포의 경우 VMFS 또는 NFS 데이터스토어를 사용할 계획을 세우고, 현재 vVols를 사용하지 않는다면 VASA Provider를 비활성화 상태로 두십시오. 각 릴리스의 vVols 지원에 대해서는 ONTAP tools 릴리스 노트를 확인하십시오.



[[protection-and-disaster-recovery]]
== 보호 및 재해 복구

.ONTAP tools for VMware vSphere를 사용하여 데이터스토어를 보호하려면 어떻게 해야 합니까?
iSCSI 또는 FC 프로토콜을 사용하는 적격 VMFS 데이터스토어를 Asynchronous 또는 AutomatedFailOverDuplex 정책을 사용하는 SnapMirror 관계와 함께 보호 그룹에 추가하여 보호할 수 있습니다. 호스트 클러스터에 여러 SVM의 데이터스토어가 포함된 경우, 세분화된 데이터스토어 보호 워크플로를 사용하여 보호 그룹 수준에서 데이터스토어를 선택하고 보호하십시오. 단계는 link:manage/protect-ds.html["ONTAP tools에서 VMFS 데이터스토어 보호"] 및 link:protect/protect-multiple-ds.html["ONTAP tools를 사용하여 클러스터의 데이터 저장소 보호"]를 참조하십시오.

.ONTAP 툴을 재해 복구에 어떻게 사용할 수 있습니까?
어레이 기반 재해 복구를 위해 ONTAP tools에서 SRA 서비스를 활성화하고 VMware Live Site Recovery 어플라이언스에 SRA 어댑터를 설치하십시오. SRA 워크플로를 실행하기 전에 소스 및 대상 클러스터에서 동일한 사용자 지정 SnapMirror 일정을 사용하십시오. 새로운 SRA 설정에서는 항상 테스트 페일오버를 실행하십시오. 생략하면 재보호 작업이 실패할 수 있습니다. 설정 단계는 link:protect/enable-storage-replication-adapter.html["데이터 저장소를 보호하려면 ONTAP tools에서 SRA를 구성하십시오"]을(를) 참조하십시오.

.SRA와 VMware Live Site Recovery를 사용하여 어떤 데이터스토어 유형을 보호할 수 있습니까?
SRA는 iSCSI 및 FC에서 NFSv3 데이터스토어와 VMFS 데이터스토어를 지원합니다. NVMe-oF 데이터스토어에 대한 재해 복구는 지원되지 않으며, VMware Live Site Recovery는 NFSv4.1 또는 FlexGroup 데이터스토어에 대한 어레이 기반 복제를 지원하지 않습니다. 일관성 그룹은 iSCSI 및 FC에서만 지원되며, NFS 볼륨을 일관성 그룹에 추가하면 장치 검색이 실패합니다.

.SnapMirror 활성 동기화 보호 기능은 SRA 기반 재해 복구와 어떻게 다릅니까?
호스트 클러스터 보호 워크플로는 VMFS 데이터스토어에 SnapMirror 액티브 동기화를 사용합니다. ONTAP 툴 10.6은 세부적인 데이터스토어 보호 기능도 지원하므로 iSCSI 또는 FC를 사용하여 적합한 VMFS 데이터스토어를 선택하고 보호 그룹 수준에서 보호를 적용할 수 있습니다. 대신 SRA는 어레이 기반 재해 복구 워크플로를 위해 VMware Live Site Recovery와 통합됩니다. 적합성 세부 정보는 link:protect/granular-datastore-protection-concept.html["ONTAP 툴의 세분화된 데이터스토어 보호 자격 기준"]을(를) 참조하십시오.



[[access-control-backup-and-support]]
== 액세스 제어, 백업 및 지원

.ONTAP 툴, vCenter 및 ONTAP 전반에서 액세스 제어는 어떻게 작동합니까?
액세스는 두 가지 환경에서 제어됩니다. vCenter Server 권한은 vSphere 객체에 대한 액세스를 관리하고, ONTAP 역할은 스토리지 작업을 관리합니다. ONTAP 툴은 먼저 vCenter 역할을 확인한 다음 스토리지 백엔드와 연결된 ONTAP 역할을 확인합니다. ONTAP 툴은 vCenter 또는 ONTAP에서 사용자 계정을 생성하지 않으므로 관리자가 필요한 서비스 계정을 생성합니다. 자세한 내용은 link:concepts/rbac-learn-about.html["ONTAP tools의 RBAC에 대해 알아보십시오"]을(를) 참조하십시오.

.ONTAP tools for VMware vSphere에서 역할 기반 액세스 제어(RBAC)를 어떻게 구성합니까?
ONTAP 툴은 vCenter 또는 ONTAP에서 사용자 계정을 생성하지 않으므로 vSphere 관리자가 두 환경 모두에서 필요한 서비스 계정을 생성하고 역할을 할당해야 합니다. vCenter Server에서 ONTAP 툴은 원격 플러그인을 통해 노출되는 추가 객체로 RBAC 모델을 확장합니다. ONTAP에서는 스토리지 백엔드 인증 시 제공하는 사용자에게 할당된 ONTAP 역할을 통해 액세스가 제어됩니다. ONTAP 툴은 스토리지 백엔드 작업에 필요한 최소 권한을 할당하는 데 사용할 수 있는 사전 정의된 역할과 JSON 역할 파일을 제공합니다. 설정 단계는 link:concepts/rbac-vcenter-use.html["vCenter Server RBAC가 ONTAP tools for VMware vSphere와 함께 작동하는 방식"] 및 link:configure/configure-user-role-and-privileges.html["ONTAP tools에 대한 ONTAP 사용자 역할 및 권한을 구성합니다"]을(를) 참조하십시오.

.ONTAP 툴은 어플라이언스를 얼마나 자주 백업하며, 백업은 어떤 용도로 사용됩니까?
ONTAP tools 10.5부터 백업은 기본적으로 활성화되며 10분마다 실행됩니다. 백업 파일은 데이터스토어에 저장되며 원래 가상 머신이 손실된 경우 ONTAP tools 어플라이언스 자체를 재배포하고 복구할 수 있도록 해줍니다. 이 파일은 ONTAP tools가 관리하는 ONTAP 클러스터 또는 vCenter Server 구성의 백업이 아닙니다. 빈도를 10분에서 60분 사이로 변경할 수 있습니다. 단계는 link:manage/backup-settings.html["ONTAP 도구 백업 설정 편집"] 및 link:manage/recover-backup.html["백업에서 VMware vSphere용 ONTAP tools 복구"]을(를) 참조하십시오.

.ONTAP 툴 백업을 비활성화할 수 있습니까?
백업을 비활성화할 수는 있지만, 비활성화하지 마십시오. 백업을 비활성화하면 ONTAP 툴이 낮은 복구 시점 목표를 유지할 수 없게 됩니다. 백업을 비활성화해도 기존 백업 파일은 삭제되지 않습니다. 단계는 link:manage/backup-settings.html["ONTAP 도구 백업 설정 편집"]를 참조하십시오.

.문제 해결이나 고객 지원 문의가 필요한 경우 로그는 어디에서 찾을 수 있나요?
ONTAP 툴 Manager 또는 vSphere Client에서 로그 번들을 생성할 수 있습니다. ONTAP 툴 Manager에서 생성된 번들에는 관리되는 모든 vCenter Server 인스턴스의 로그가 포함되며, vSphere Client에서 생성된 번들은 선택한 vCenter Server로 범위가 지정됩니다. 생성된 아카이브를 다운로드하여 요청 시 기술 지원에 제공하십시오. 단계는 link:deploy/deployment-error-codes.html["ONTAP tools 배포 오류 코드"]를 참조하십시오.

.ONTAP 툴의 문제 해결을 위한 진단 정보를 어떻게 수집할 수 있습니까?
로그 번들 외에도 유지 관리 콘솔에서  `diag` 사용자 계정에 대한 원격 진단(SSH) 액세스를 활성화할 수 있습니다. 한 번에 하나의 diag 로그인 세션만 허용되며, 액세스는 다음 날 자정 또는 diag 사용자로 다시 로그인하는 즉시 자동으로 비활성화됩니다. 로그 번들에서 제공하는 것보다 더 심층적인 문제 해결을 위해 이 액세스를 사용하고, 기술 지원에서 작업할 수 있는 기준 로그를 확보할 수 있도록 먼저 로그 번들을 생성하십시오. 단계는 link:manage/configure-remote-diagnostic-access.html["ONTAP tools에 대한 원격 진단 액세스 구성"]을(를) 참조하십시오.

== 업그레이드, 마이그레이션 및 자동화

.최신 ONTAP 툴 10.x 릴리스로 바로 업그레이드할 수 있습니까?
최신 릴리스 바로 이전 두 릴리스(N-2)에서 직접 업그레이드가 지원됩니다. 버전이 더 오래된 경우, 먼저 최신 릴리스로의 직접 업그레이드를 지원하는 가장 오래된 릴리스로 업그레이드한 다음 최신 릴리스로 다시 업그레이드하십시오. 실패한 업그레이드는 항상 롤백할 수 있는 것은 아니며 복구는 낮은 RPO 백업이나 스냅샷 복구에 의존하므로, 시작하기 전에 낮은 RPO 백업을 활성화하고 백업을 다운로드하십시오. 지원되는 업그레이드 경로 및 단계는 link:upgrade/upgrade-ontap-tools.html["VMware vSphere 10.x용 ONTAP tools에서 10.6으로 업그레이드"]을(를) 참조하십시오.

.ONTAP tools 9.x에서 최신 10.x 버전으로 마이그레이션하려면 어떻게 해야 합니까?
마이그레이션은 특정 ONTAP 툴 9.x 릴리스에서만 지원됩니다. 마이그레이션 경로는 환경에서 vVols를 사용하는지 여부에 따라 달라집니다. vVols가 있는 환경은 VASA Provider를 마이그레이션하고 SRA를 업데이트하는 반면, NFS 및 VMFS 데이터스토어만 있는 환경은 9.x 배포를 제거하고 10.x를 배포합니다. ONTAP 툴 10.x는 VMFS 데이터스토어에서만 NVMe-oF를 지원하므로 마이그레이션 후 NVMe/FC를 사용하는 vVols 데이터스토어는 작동하지 않게 됩니다. 지원되는 소스 릴리스 및 단계는 link:migrate/migrate-to-latest-ontaptools.html["VMware vSphere 9.xx용 ONTAP tools에서 10.6으로 마이그레이션"]를 참조하십시오.

.REST API를 사용하여 ONTAP 툴 작업을 자동화할 수 있습니까?
예. ONTAP 툴은 ONTAP 클러스터 REST API와는 별도로 자동화를 위한 REST API를 제공합니다. API 액세스는 ONTAP 툴 IP 주소와 포트 8443을 사용합니다. ONTAP 툴 Manager 자격 증명으로 인증하여 액세스 토큰을 얻은 다음,  `x-auth` 헤더에 토큰을 전송합니다. 장시간 실행되는 작업은 비동기적으로 실행될 수 있으며 모니터링할 작업을 반환합니다. 시작하려면 link:automation/learn-rest-api.html["ONTAP 도구 REST API에 대해 알아보십시오"] 및 link:automation/first-call.html["첫 번째 ONTAP tools REST API 호출"]를 참조하십시오.
